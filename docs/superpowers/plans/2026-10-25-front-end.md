# Front End Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The game boots as X6 does (Capcom logo, load, opening movie, title, main menu). GAME START
starts the intro stage, and a clear of the intro stage opens the stage select screen with the boss
stages.

**Architecture:** A pure state machine `frontend/FrontEnd` runs the X6 front-end states at 60
updates/s and is tested headless. `screen/FrontEndScreen` draws it: movie frames (PNG per frame,
streamed), the title background and the text sprites cut from the RE images, the black fade.
`X6Game` routes front end → intro → stage select.

**Tech Stack:** Java 17, LibGDX 1.14.2 (`Texture`, `Pixmap`, `Music`), JUnit 5.

**Spec:** the user's request (2026-10-25): "1. our game boots up same as the x6 game: logo screen,
anime movie, loading screen, main menu 2. pressing "start game" on the main menu loads the intro
stage 3. after beating the intro stage, then we go to the "level select" screen"; "use the PNGs in
`re/front-end/images/`". Behaviour source: [`~/IdeaProjects/mmx-demake-tools/docs/engine.md`](../../re/findings/engine.md), "Front
end", and [`~/mmx-data/x6/re/front-end/notes.md`](../../re/work/front-end/notes.md).

## Global Constraints

- The order is the X6 order, read from the code: logo → load → opening → title (PRESS START) →
  menu. The user's list puts the load after the opening and has no title. The plan follows X6
  ("same as the x6 game"). The handoff tells the user, so they can confirm or change it.
- Game data loads at run time from the data root. Nothing is copied into the repo.
  - Movies: `<root>/movies/caplogo/` and `<root>/movies/x6op/` (`frame-NNNN.png`, 320 × 240;
    `audio.wav`, 37 800 Hz stereo).
  - Images: `<root>/re/front-end/images/`.
- Timing is in updates at 60/s (`StepClock`). One movie frame = 4 updates (15 fps).
- X6 values (all [certain] from the code unless marked):
  - Fades: `FadeIn(8)` and `FadeOut(8)` move a level of 0–255 by 8 per update, so 32 updates
    (`FadeTask` `0x80013530`, read this session).
  - Logo: 90 frames (`movie_table` row 0 `play_frames`) [likely: `BootTask` calls the player
    directly].
  - Opening: 1518 frames (row 1). Skip buttons: `0x08F0` (Start or a face button).
  - Title: 600 updates from the fade-in. PRESS START BUTTON blinks 16 of each 32 updates. Start
    skips to the menu.
  - Menu: three rows. Up and Down wrap and play bank 0 sound 12. Start or Cross picks and plays
    bank 0 sound 34. After 18 001 passes with no new press, the menu fades out to the opening.
  - Sounds are bank 0: `PlaySound(0, 12)` and `PlaySound(0, 34)` at `0x8001CFB4`–`0x8001D04C`
    (read this session).
- No XA music on the title or the menu [likely: the stream play flag `0x800E2E5C` is 0 in
  `title-4_press-start` and `title-5_main-menu`, and 2 in `intro-1_start`]. The movies play their
  own `audio.wav`.
- Display: movies are 320 × 240 and drawn ×3. The title and the menu are 512 × 240 and stretched
  to 960 × 720 (x × 1.875, y × 3), as the PS1 shows both modes on one 4:3 screen.
- No code comments, except a `TODO` per guess in the format
  `// TODO: <what> (docs/gaps.md, "Front end")`. Each guess gets a line in `docs/gaps.md`.
- Commit only when the user asks. Then split by task and end each message with
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Tests that need the data call `Assumptions.assumeTrue(DataPaths.defaultRootExists())`.

## Review Focus

1. Start held from the title into the menu must not pick GAME START at once. Only a new press after
   the menu fade-in counts (Task 2, `heldStartDoesNotPickOnTheMenu`).
2. A press during a fade must do nothing: no double sound, no skip of a skip (Task 2,
   `pressDuringFadeIsIgnored`).
3. A skip of the opening must stop its audio. A run back to the opening (title timeout, menu idle)
   must restart the audio from 0 (Task 4, by eye and ear; Task 2, `titleTimeoutReturnsToOpening`
   checks the phase and frame 0).
4. Memory: the opening has 1527 PNG frames. Only one frame texture may be alive at a time (Task 3,
   `MovieFrames` disposes the old texture; Task 6 checks the process memory).
5. Escape in the intro stage returns to the title, not to the stage select. A clear of the intro
   opens the select screen, which lists no intro stage (Task 5, `X6FlowTest`).

### Task 2: The front-end state machine

**Files:**
- Create: `src/main/java/mmx/x6/frontend/Phase.java`, `src/main/java/mmx/x6/frontend/FrontEnd.java`
- Test: `src/test/java/mmx/x6/frontend/FrontEndTest.java`

**Interfaces:**
- Consumes: `Fade`, `Buttons` bits, `audio.Sfx`.
- Produces:
  - `enum Phase { LOGO, LOAD, OPENING, TITLE, MENU }`;
  - `FrontEnd(Sfx sfx, Phase start)`;
  - `void update(int held)`: one update. It keeps its own previous `held` value to find new
    presses;
  - getters: `Phase phase()`, `int phaseUpdates()` (0 on the first update of a phase),
    `int movieFrame()` (`phaseUpdates / 4` in LOGO and OPENING), `int row()`,
    `boolean textShown(int textVar)`, `float darkness()`, `boolean startGame()` (true once GAME
    START has faded out).
- Constants (public): `LOGO_FRAMES = 90`, `OPENING_FRAMES = 1518`, `UPDATES_PER_FRAME = 4`,
  `LOAD_UPDATES = 60`, `TITLE_UPDATES = 600`, `MENU_IDLE = 18001`, `FADE_SPEED = 8`,
  `SOUND_MOVE = 12`, `SOUND_PICK = 34` (bank 0).

Rules (from `engine.md`, "Front end", and the notes):

| phase | enters with | leaves |
|---|---|---|
| LOGO | no fade | after `LOGO_FRAMES × 4` updates → LOAD. A Start press → LOAD at once |
| LOAD | no fade | after `LOAD_UPDATES` → OPENING. No skip |
| OPENING | no fade | after `OPENING_FRAMES × 4` → TITLE. A press of `START`, `JUMP`, `BUSTER`, `DASH` or `WEAPON` (the face buttons): sound 34, fade out, then TITLE |
| TITLE | fade in; the 600 timer starts with it | at 0: fade out, then OPENING (X6 runs a demo here). A `START` press: sound 34, fade out, then MENU |
| MENU | fade in, row 0 | Up and Down (row 0 → 2 and 2 → 0), sound 12. `START` or `JUMP` (Cross): sound 34, fade out. Row 0: `startGame()` is true. Rows 1 and 2: no effect. 18 001 passes with no new press: fade out, then OPENING |

- Presses count only when no fade is busy. That is the X6 rule: "Most sub-steps wait for
  `fade_dir` = 0".
- `textShown(4)` (PRESS START BUTTON, title) and `textShown(5)` and `textShown(7)` (menu) are true
  when `(phaseUpdates & 0x10) == 0`. The other `var` values are always shown in their phase.

  - draw `MovieFrames.frame(movieFrame())` at 960 × 720;
  - on the first update of the phase, start `Gdx.audio.newMusic(movieAudio)` from 0;
  - on any phase change, stop and dispose the music.

    `(x − ox) × 1.875, (y − oy) × 3`, with size `w × 1.875, h × 3`.

- Sounds: `sfx` is a `CachedSfx` over `SoundBanks.load(paths)` (bank 0 = `m087-e04`), made by

- Screenshots: `-Dmmx.shot` and `-Dmmx.shotAfter`. Read the back buffer with
